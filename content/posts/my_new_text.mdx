Before sketching, I read the OpenBridge documentation end to end with one
question in mind: where does it address the operator *learning* the interface,
rather than *using* it?

## First observations

The component documentation is written for the people building bridge systems.
That is the right audience for a design system, but it means the operator
appears mostly as a set of constraints — glare, gloves, motion, fatigue —
rather than as someone whose understanding develops over time.

The day, dusk and night themes are the clearest example of the system taking
context seriously. There is no equivalent axis for experience.

## Open questions

- Is "novice mode" a category error on a bridge, where predictability matters
  more than accommodation?
- Could guidance attach to the component library itself, so it stays consistent
  across vendors the way visual style already does?
